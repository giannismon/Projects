# Terraform Azure AKS + PostgreSQL

Deploys a production-ready Azure Kubernetes Service (AKS) cluster with a private PostgreSQL Flexible Server and Key Vault for secret management, using Terraform modules.

## Architecture

```
Terraform_Azure_AKS_PostgreSQL/
├── main.tf
├── variables.tf
├── providers.tf
├── terraform.tfvars
├── outputs.tf
└── modules/
    ├── network/
    │   ├── main.tf
    │   ├── variables.tf
    │   └── outputs.tf
    ├── keyvault/
    │   ├── main.tf
    │   ├── variables.tf
    │   └── outputs.tf
    └── postgres/
        ├── main.tf
        ├── variables.tf
        └── outputs.tf
```

## Deployment Order

Terraform creates resources in this order based on dependencies:

1. **Resource Group** — everything else depends on it
2. **User Assigned Identities** (x2) — for the AKS cluster and the application
3. **Random suffix + password** — generated once, reused across resources
4. **Network** + **Key Vault** — parallel; Key Vault deploys to a separate subscription
5. **PostgreSQL** — requires the delegated subnet and private DNS zone (networking)
6. **AKS Cluster** — requires the AKS subnet and the identities

## Infrastructure Components

| Resource | Description |
|---|---|
| Resource Group (`rg-<prefix>`) | Groups AKS, networking, and PostgreSQL |
| Resource Group (`rg-<prefix>-kv`) | Separate resource group for Key Vault (different subscription) |
| User Assigned Identity (`id-<prefix>-cluster`) | Identity used by the AKS control plane |
| User Assigned Identity (`id-<prefix>-app`) | Identity used by workloads running in AKS to read Key Vault secrets |
| VNet + 2 Subnets | AKS subnet (`10.0.1.0/24`) and PostgreSQL delegated subnet (`10.0.2.0/24`) |
| Private DNS Zone | Enables AKS pods to resolve the PostgreSQL FQDN privately |
| Key Vault | Stores the auto-generated PostgreSQL password |
| PostgreSQL Flexible Server v16 | Private only — no public endpoint, accessible only from within the VNet |
| AKS Cluster | 2-node system pool, Azure CNI networking, User Assigned Identity |

## Key Design Decisions

### Private PostgreSQL
The PostgreSQL server has `public_network_access_enabled = false`. It is only reachable from pods running inside AKS via the private delegated subnet and private DNS zone.

### Key Vault in a Separate Subscription
The Key Vault is deployed to a different Azure subscription (`903ad9f0-...`) using a second `azurerm` provider alias. This is useful when secrets must be centrally managed across multiple projects or subscriptions.

### Auto-generated Password
The PostgreSQL password is generated by Terraform using `random_password` and stored in Key Vault. It is never written to `terraform.tfvars`. To retrieve it after deployment:

```bash
az keyvault secret show \
  --vault-name <key_vault_name> \
  --subscription 903ad9f0-00e9-470f-9a53-d430f73dcd0d \
  --name postgres-password \
  --query value -o tsv
```

## Setup

### 1. Set your Azure subscription

```bash
az login
az account set --subscription "<YOUR_SUBSCRIPTION_ID>"
```

### 2. Configure variables

Edit `terraform.tfvars`:

```hcl
prefix   = "myapp"
location = "West Europe"
```

### 3. Deploy

```bash
terraform init
terraform plan
terraform apply -auto-approve
```

### 4. Connect to AKS

```bash
az aks get-credentials --resource-group rg-myapp --name aks-myapp
kubectl get nodes
```
